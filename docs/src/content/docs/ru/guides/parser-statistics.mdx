Статистика парсера — диагностическое окно, которое показывает, сколько времени заняла обработка
каждого трейс-файла по фазам конвейера за текущую сессию. Это инструмент разработчика, по
умолчанию выключен.

## Включение

<Steps>

1. Откройте **Настройки** (`Ctrl/Cmd+,`).
2. Включите переключатель **Статистика парсера** — «Открывает диагностический инструмент
   парсера. По умолчанию выключен.»
3. В верхнем меню появится новый пункт — **Статистика парсера**.

</Steps>

## Сводка

Верхний блок агрегирует сессию целиком. Первый ряд:

| Карточка | Значение |
| --- | --- |
| Файлов | Количество обработанных файлов |
| Событий | Всего событий по всем файлам |
| Общий размер | Суммарный размер исходных файлов |
| На событие | Среднее время обработки одного события, в микросекундах |
| Пропускная способность | Событий в секунду (фаза обработки) |

Второй ряд суммирует фазы конвейера в миллисекундах:

| Фаза | Что покрывает |
| --- | --- |
| Скачивание | Скачивание файла с удалённого сервера (`0` для локальных файлов) |
| Парсинг / чтение | Получение событий: парсинг или чтение из локального хранилища |
| Запись в стор | Запись событий в хранилище (`0`, если хранилище выключено или файл из кэша) |
| Добавление в UI | Добавление событий в рабочий набор и отрисовку карточек |
| Финализация (фильтры/статистика) | Пересчёт фильтров, сортировок и статистики за сессию |

## Таблица по файлам

Одна строка на файл, сортировка по суммарному времени — самые долгие сверху.

| Колонка | Значение |
| --- | --- |
| Файл | Имя файла |
| Ист. | Как события попали в приложение: `local` (разобран с диска), `remote` (разобран после скачивания), `cache` (прочитан из хранилища) |
| События | Число событий файла |
| Размер | Размер исходного файла |
| Скач., мс | Время скачивания |
| Парс., мс | Время получения событий |
| Запись, мс | Время записи в хранилище |
| UI, мс | Время добавления в UI |
| Событий/с | Пропускная способность обработки файла |

## Обновить и очистить

**Обновить** перечитывает снимок из памяти и перестраивает таблицу. **Очистить** сбрасывает все
метрики сессии. Метрики живут только в памяти — при перезапуске приложения они сбрасываются.

## Как читать числа

- Большая доля **Скачивания** указывает на скорость сети или размер файлов, а не на приложение.
- Большая доля **Парсинга / чтения** растёт на сложных правилах и объёме SQL-параметров —
  сравнивайте файлы похожего размера, чтобы найти выбросы.
- **Запись, мс** важна только при включённом локальном хранилище; с выключенным остаётся `0`.
- Всплески **UI, мс** означают, что в рабочий набор одновременно попало много событий.
- **Финализация** начисляется один раз на батч, а не на файл — она видна в итогах, но не в
  строках таблицы.
