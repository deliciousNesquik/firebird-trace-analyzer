Инспектор событий — диагностическое окно, которое восстанавливает жизненный цикл соединения с
базой данных за выбранным событием. Нажмите **Просмотр** на карточке события, и окно перечислит
все события этого соединения в порядке времени, подсветив выбранное.

<Aside type="caution" title="Экспериментально">
Функция помечена как экспериментальная: события группируются в жизненный цикл соединения по
общему attachment id и времени. Границы соединения могут быть неточными, если в трассировке нет
записей attach/detach.
</Aside>

## Включение

<Steps>

1. Откройте **Настройки** (`Ctrl/Cmd+,`).
2. Включите переключатель **Инспектор событий** — «Открывает диагностический инструмент для
   событий. По умолчанию выключен.»
3. В нижней части каждой карточки события появится кнопка **Просмотр**, компактные варианты
   включительно.

</Steps>

## Открытие цепочки

Нажмите **Просмотр** на любой карточке события (подсказка: «Открыть инспектор события»).
Откроется отдельное окно с цепочкой для этого события; заголовок повторяет тип события и
время, например `Event Inspector — Statement Start @ 2026-11-18 10:00:00`.

Цепочка строится в момент нажатия из событий, загруженных в текущей сессии, с фильтром по той же
сессии трассировки, что и выбранное событие. После переразбора или загрузки новых файлов цепочки
учитывают новые данные при следующем нажатии.

## Что содержит цепочка

Одна цепочка соответствует одному соединению:

- **Сопоставление по attachment id.** В цепочку попадают все события с тем же attachment id,
  что и у выбранного события.
- **Границы по времени.** Окно простирается от ближайшего attach до выбранного события до
  ближайшего detach после него, поэтому в цепочке лежат выражения этого соединения, вызовы
  процедур и триггеров, ошибки и сама пара attach/detach.
- **Переиспользование attachment id обрабатывается.** Если id был переиспользован более поздним
  соединением, цепочка останавливается на соседнем attach или detach, а не смешивает два
  соединения в одно.
- **Границы сессии трассировки.** В цепочку добавляются ближайший trace init до соединения и
  ближайший trace fini после него.
- **Обзор сессии для событий уровня сессии.** Нажатие на карточке trace init или trace fini
  показывает всю сессию: её пары attach/detach плюс границы init/fini.

События упорядочены по времени. Выбранное событие подсвечено акцентной полосой слева, а в
заголовке видна сводка вида «12 related event(s) in the lifecycle chain».

## Как читать цепочку

Типичная цепочка: trace init, attach, выражения с их процедурами и триггерами, ошибки, detach,
trace fini. Используйте её, чтобы увидеть, что ещё выполнялось на том же соединении рядом с
медленным или неудачным выражением — предыдущие ошибки, выражения с блокировками или глубину
вызовов вокруг процедуры, не покидая окна.

## Ограничения

- **Неполные цепочки.** Если в трассировке нет записей attach/detach, границы по времени
  определить нельзя; в заголовке висит постоянное предупреждение: «Если в трассировке нет
  записей attach/detach, цепочка может быть неполной.»
- **Не сохраняется.** Цепочка — это представление над загруженными событиями: она не сохраняется
  вместе с сессией и не попадает в экспорт отчётов.
