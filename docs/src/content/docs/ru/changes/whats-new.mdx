## 1.17.0 — 27 ноября 2026

Этот релиз делает горячие клавиши настраиваемыми и перестаёт молча терять данные: предупреждения
парсера и счётчики пропущенных блоков теперь видны в UI и логах. Тесты выросли до 294
(118 парсер + 176 приложение), все зелёные.

### Новые возможности

- Настраиваемые горячие клавиши: новая страница **Горячие клавиши** в настройках позволяет
  переназначить любое действие — записать комбинацию, занять занятое, отключить действие,
  сбросить одно или все. Изменения применяются сразу (включая нативное меню macOS) и хранятся
  в `shortcuts.json` только как оверрайды, с опубликованной JSON-схемой для ручного редактирования.
  Шаблонам отчётов можно назначить сочетания запуска. Сочетание самих настроек (`Ctrl+,` / `⌘,`)
  заблокировано.
- Диалог «Статистика парсера» (режим разработчика) получил колонку **Пропущено** по файлам и
  сумму за сессию: блоки, которые парсер не смог превратить в события (severity не ниже
  Warning). Файлы, перечитанные из локального хранилища, показывают `—` (неизвестно), а не ноль:
  предупреждения пока не персистятся.

### Улучшения

- Предупреждения парсера больше не теряются: открытие файла с частичным разбором пишет в
  app-лог суммарную строку (число событий, предупреждений, ошибок); построчные детали остаются
  в parser.log.
- Уровни логов пересмотрены по одному критерию (завершённая с видимым фидбеком операция
  пользователя — не Error); стартовый баннер пишет версию приложения, ОС и пути к логам;
  лог сбрасывается на диск при необработанном исключении.
- Раньше молчавшие catch-блоки (создание папки логов, проекции значений отчётов, листинги SSH,
  очистка исходных файлов) теперь пишут предупреждения.

### Документация

- Шаблон плагина и SDK-доки демонстрируют быстрый путь `SortDescriptor.KeySelector` (ключ
  извлекается один раз на событие); таблица неисправностей в README плагина теперь цитирует
  реальные сообщения лога.
- Страница «Горячие клавиши» документирует процесс настройки и формат файла оверрайдов.

## 1.16.0 — 18 ноября 2026

Релиз объединяет исправления корректности парсера по итогам полного ревью кода и улучшения
интерфейса: новые раскладки списка событий, производные длительности, нативное меню macOS, тосты и
единая схема горячих клавиш. Тесты выросли с 98 до 240 (118 парсер + 122 приложение), все зелёные.

### Критические изменения

- `ParseStreamAsync` больше не закрывает поток вызывающего (#36): код, полагавшийся на
  автоматическое закрытие, должен освобождать поток сам.
- Per-call `ParseOptions` теперь доходят до обработчика событий (#32): установка
  `ParsePerformanceTables = false` реально отключает парсинг таблиц — раньше вне DI-маршрута
  опция игнорировалась.
- Отсутствующие обязательные ключи правил теперь fail-fast при загрузке с понятным сообщением
  (#33) вместо per-block предупреждений «ключ не найден» при разборе.
- Некорректные `ParseOptions` (неположительные `BatchSize`/`MaxBlockLines`, нулевой
  `RegexTimeout`) бросают исключение на входе вместо пустого разбора со спамом предупреждений
  (#40).

### Новые возможности

- Добавлен переключатель Компакт/Полный для списка событий: однострочные компактные строки для
  всех семейств событий, выровненные колонки и показ длительности.
- Добавлены производные длительности, считаемые при загрузке (парс, чтение из хранилища,
  восстановление сессии): время жизни процесса (fini − init одного процесса, если его attach был
  виден) и подключения (detach − attach, даже когда пара в разных файлах), в сортируемом поле
  `Duration`.
- Добавлены потоковые диагностики: предупреждения доставляются стриминговому потребителю через
  `IObserver<ParsingWarning>` (#34).
- `ParseStreamAsync` репортит прогресс (#35); `Parse` принимает `CancellationToken` (#51).
- Добавлено нативное меню macOS, зеркалирующее полное главное меню, включая динамические отчёты.
- Добавлены тосты (успех/предупреждение/ошибка, снизу-справа) и уведомления фоновых задач для
  загрузок, переразбора и генерации отчёта.
- Добавлены анимации показа/закрытия модальных окон.
- Добавлена единая схема горячих клавиш (`Ctrl/Cmd+1..5` секции, `Esc` отмена, `,` настройки,
  `Ctrl+F` поиск, `Ctrl+W`/`Shift+W` закрытие вкладок), задокументированная на новой странице
  «Горячие клавиши».

### Улучшения

- Perf-таблицы переживают частичный набор колонок (#38).
- События без значения для поля сортировки всегда в конце списка.
- Убран вводящий в заблуждение курсор-рука с некликабельных полей карточек.
- Меньше аллокаций на горячем пути (#41); rules.json парсится один раз вместо двух (#46);
  логирование на шаблонах NLog (#49); мёртвое правило performance_table_row удалено (#47).

### Исправления

- Кэш подключений ключуется парой (база, attachment id): пользователь/роль/charset больше не
  переносятся между базами при переиспользовании номеров ATT в Firebird Classic (#31).
- Исправлено открытие диалога поверх уже открытого модального окна, в том числе из нативного меню.
- Кнопка очистки лога парсера в настройках чистит parser.log вместо application.log.
- Мусор после perf-таблицы больше не создаёт фантомных строк (#39).
- У событий с неразбираемым timestamp появился warning (#37).
- Обработка regex-таймаута покрывает оба матча заголовка (#45).
- Фатальные исключения больше не превращаются в per-block предупреждения (#44).

### Инфраструктура

- Тесты выросли с 98 до 240 (118 парсер + 122 приложение) (#53).
- Релизные сборки идут на образе macOS 15; гайд по сборке и заметки релиза переведены на
  английский.
- Зависимости: SSH.NET 2026.0.0, System.Text.Json 11.0.0 (GA), Astro 7.4.12.

### Примечания

- Bundle id macOS изменён на `com.deliciousnesquik.firebirdtraceanalyzer`: macOS может считать
  обновлённое приложение новым и повторно запросить разрешения.
- Сообщения валидации парсера только на английском (#48).

## 1.15.0 — 28 августа 2026

Фильтрация по цепочке ошибок, разделение режима разработчика, переработанные кнопки панели и новая иконка.

### Новые возможности

- Добавлена фильтрация по полям внутри цепочки ошибок — **Код ошибки** и **Сообщение ошибки**. Они
  лежат в коллекции у событий-ошибок и раньше были недоступны; теперь событие проходит, если
  совпадает любая строка его цепочки. Фильтры появляются, когда вид сужен до ошибок.
- Единый *Режим разработчика* разделён на два независимых переключателя — **Статистика парсера** и
  **Инспектор событий**. Кнопка инспектора на карточке видна только при включённом Инспекторе;
  ненадёжный пункт из контекстного меню убран.

### Улучшения

- Переработаны кнопки поиска / сортировки / фильтрации: на кнопке фильтра бейдж с числом активных
  фильтров, на кнопке поиска — индикатор активности; единый стиль кнопок и уменьшенный радиус
  скругления.
- Новая иконка приложения.

### Исправления

- Кнопка копирования в карточке ошибки и цвет иконки в окне настроек.
- Вид плагинов: цвет иконки, секция коллизий скрывается, если их нет.
- Видимость пустого состояния списка событий и более точные человекочитаемые размеры файлов.

## 1.12.0 — 23 июля 2026

Большой проход по безопасности, производительности и устойчивости ядра и приложения, плюс крупная
чистка внутренней архитектуры.

### Безопасность

- Проверка ключа хоста SSH (доверие при первом подключении через `known_hosts`) против атак
  «человек посередине».
- Пароли и парольные фразы ключей больше не пишутся в SSH-профили.
- Запасное хранилище учётных данных шифруется AES-256-GCM.
- Защита от path traversal для скачанных имён файлов и id шаблонов отчётов.
- Пароль в keychain на macOS передаётся через stdin, а не через командную строку.

### Производительность

- Разбор трейса идёт вне UI-потока; предикаты фильтров компилируются один раз за проход, а ключи
  сортировки извлекаются один раз на событие.
- Ускорены экспорт в PDF и XLSX; оптимизирован горячий путь парсера (кэш regex, меньше аллокаций).
- Устранён N+1 в хранилище событий.

### Устойчивость

- Глобальные обработчики сбоев отправляют фоновые падения в лог вместо тихого выхода.
- Конвейер фильтров работает по снимку — исправлена гонка при загрузке или закрытии файлов.
- Защита от OOM на битых логах через ограничение размера блока.

### Архитектура

- Главная view-model разбита на сфокусированные сервисы с внедрением зависимостей; `IEventStore`
  разделён по ролям; карточки событий получили общие базовые классы; добавлен новый набор тестов
  парсера.

## 1.11.0 — 17 июля 2026

Аналитика и обслуживание хранилища событий: read-only SQL-консоль и сжатие для возврата места на диске.

### Новые возможности

- Добавлена read-only SQL-консоль по хранилищу событий: подсветка SQL, автодополнение (ключевые
  слова, схема, колонки по table./alias., список таблиц после `FROM`/`JOIN`), карта схемы карточками
  с поиском и зум шрифта редактора (`Ctrl`+колесо, `Ctrl` +/-/0).
- Добавлено обслуживание хранилища: **Сжать** возвращает место на диске (`VACUUM` + чистка сирот) и
  также выполняется автоматически в фоне при следующем запуске после удалений; подтверждения перед
  удалением выбранных файлов или очисткой всего хранилища.

### Улучшения

- Фильтры и сортировки считаются в фоне с индикатором загрузки.
- Современный вид окна хранилища; исправлена сетка карточек событий.

### Исправления

- Корректно разбираются таблицы производительности, в том числе для процедур и триггеров.

## 1.10.1 — 13 июля 2026

Патч безопасности и удалённых подключений.

### Безопасность

- Пароль хранится в хранилище учётных данных ОС (Secret Service / `secret-tool` на Linux) и больше
  не задерживается в памяти после подключения.

### Производительность

  ресурсы при отключении.

## 1.10.0 — 13 июля 2026

Опциональное локальное хранилище событий, новые типы фильтров и заметное ускорение.

### Новые возможности

- Добавлено опциональное локальное хранилище событий (SQLite/WAL): сохраняет разобранные сессии и
  мгновенно открывает их заново вместо повторного разбора; настройка режима хранения; диалог
  восстановления сессии при старте.
- Добавлено управление хранилищем: статистика, разбивка размера базы, экспорт/импорт между
  машинами и «загрузить в сессию» из хранилища.
- Добавлен текстовый фильтр «содержит» (`TextSearch`) в панели и конструкторе отчётов; фильтры по
  boolean-полям; SQL трактуется как текстовый фильтр.
- Добавлена статистика парсера по фазам, с режимом разработчика.
- Добавлен переиспользуемый индикатор фоновых задач со статусом записи в хранилище; выбор
  удалённых файлов нажатием по карточке.

### Производительность

- Целочисленный `file_id` вместо хеша файла и прополка индексов (резкое сокращение размера базы);
  фоновая очередь записи сняла диск с критического пути разбора; мемоизация SQL-текста устранила N+1.

### Исправления

- Имена файлов убраны из заголовка PDF; исправлены ширины колонок встроенных отчётов; починен флаг
  сортировки по умолчанию.

## 1.0.0 — 18 июня 2026

Первый релиз — кроссплатформенное десктоп-приложение, которое превращает трейс- и аудит-логи Firebird
в структурированные типизированные события.

- Потоково читает и разбирает трейс-файлы любого размера вне UI-потока.
- Загружает логи из локальных файлов или удалённо по SSH/SFTP.
- Типизированные карточки для каждого типа события трассировки.
- Фильтры (мультивыбор, числовой/дата-диапазон, текст), стабильная сортировка по нескольким ключам и
  полнотекстовый поиск.
- Конструктор отчётов с теми же фильтрами, что и на главной, и экспорт в PDF, DOCX, XLSX и CSV.
