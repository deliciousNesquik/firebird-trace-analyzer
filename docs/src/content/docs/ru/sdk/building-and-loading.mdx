## Файл проекта

Плагин — это обычная библиотека классов `net10.0`, ссылающаяся на два SDK-проекта (или на
поставляемые сборки). Ключевая деталь — `Private="false"`: хост уже загружает `FirebirdTraceAnalyzer`
и `FirebirdTraceParser`, поэтому ваш пакет **не** должен нести их собственные копии — дублирование
даёт рантайму две разные идентичности одного типа, и приведение к `IAnalyzerPlugin` падает.

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Private="false" PrivateAssets="all"
                      Include="..\FirebirdTraceAnalyzer\FirebirdTraceAnalyzer.csproj" />
    <ProjectReference Private="false" PrivateAssets="all"
                      Include="..\FirebirdTraceParser\FirebirdTraceParser.csproj" />
  </ItemGroup>

</Project>
```

Если вы собираете против поставляемых DLL, а не исходных проектов, используйте элементы `<Reference>`
с тем же `Private="false"` — эффект тот же: ссылка для компиляции, без копирования в выходной каталог.

## Сборка

```bash
dotnet build TemplatePlugin
```

На выпуск идёт единственная DLL плагина (например, `TemplatePlugin.dll`). Если ваш плагин тянет
**свои** сторонние пакеты, эти DLL едут вместе с ним — см. шаг установки.

## Установка

<Tabs>
  <TabItem label="Из приложения">
    Откройте экран **Плагины** и воспользуйтесь **Установить**. Принимается одиночный `.dll` или
    `.zip`-пакет (заархивированная папка с DLL и её собственными зависимостями). Приложение само
    копирует его в отдельную подпапку. Изменения вступают в силу при **следующем запуске**.
  </TabItem>
  <TabItem label="Копирование вручную">
    Скопируйте DLL плагина в его **отдельную подпапку** каталога плагинов. DLL должна лежать в
    подпапке, а не прямо в `Plugins/` — сканер читает только подпапки.

    | ОС      | Путь |
    | ------- | ---- |
    | Windows | `%AppData%\FirebirdTraceAnalyzer\Plugins\<name>\YourPlugin.dll` |
    | macOS   | `~/Library/Application Support/FirebirdTraceAnalyzer/Plugins/<name>/YourPlugin.dll` |
    | Linux   | `~/.config/FirebirdTraceAnalyzer/Plugins/<name>/YourPlugin.dll` |

    На экране плагинов есть действие **Открыть папку плагинов**, которое ведёт прямо туда.
  </TabItem>
</Tabs>

<Aside type="caution" title="Не поставляйте SDK-сборки">
Никогда не кладите `FirebirdTraceParser.dll` или `FirebirdTraceAnalyzer.dll` в папку плагина — их
предоставляет приложение. А вот **свои** сторонние зависимости плагина кладите рядом с его DLL в ту же
подпапку.
</Aside>

После установки **перезапустите приложение**. Обнаружение и регистрация происходят один раз при
старте — горячей перезагрузки нет.

## Как работает загрузка

<Steps>

1. **Скан.** При старте приложение сканирует каталог плагинов и **каждую его подпапку**, беря все
   `*.dll` верхнего уровня.

2. **Изоляция.** Каждая сборка грузится в свой `AssemblyLoadContext`, чтобы версии зависимостей
   плагина не ломали приложение. Общие SDK-типы разрешаются обратно на уже загруженные копии хоста.

3. **Инстанцирование.** Каждый не-абстрактный публичный класс, реализующий `IAnalyzerPlugin`,
   создаётся через `Activator.CreateInstance()`. **У класса должен быть публичный конструктор без
   параметров.**

4. **Пропуск SDK.** `FirebirdTraceParser.dll` намеренно пропускается, если найдена в папке плагина.

5. **Регистрация.** Сортировки идут в сервис сортировки, фильтры — в сервис фильтрации. `GetSorts()`
   и `GetFilters()` вызываются каждый внутри `try/catch` по-плагинно — плагин, бросивший исключение,
   пропускается и логируется, а приложение всё равно стартует.

</Steps>

## Включение, выключение и коллизии

Экран **Плагины** перечисляет всё обнаруженное — имя, автор, версия и статус (Активен, Выключен,
Затенён, Ошибка загрузки) — и позволяет включить или выключить каждый. Сборка выключенного плагина
даже не загружается, поэтому его код никогда не исполняется. UI управления описан в
[руководстве по плагинам](../guides/plugins.md).

Загрузчик ключует регистрацию по **`Id`** дескриптора и разрешает коллизии одинаковых `Id`, оставляя
**старшую `Version`** и затеняя остальные. `Version` и `Author` информационные — они появляются только
в логе, никогда в списках сортировок/фильтров.

| Ситуация | Результат |
| --------- | --------- |
| Заменили старую DLL новой, те же id дескрипторов | Чистое обновление: новая логика регистрируется при следующем запуске; пункт в UI прежний. |
| Оставили обе версии рядом, те же id дескрипторов | Коллизия: одна побеждает (словарь перезаписывает), другая исчезает; перезапись логируется. Удалите старую DLL. |
| Обе версии рядом, разные id дескрипторов | Обе появляются как независимые, дублирующие пункты. |

Чтобы обновить плагин: **замените** его DLL (сохранив id дескрипторов), затем перезапустите.

## Траблшутинг

Логи лежат рядом с папкой плагинов — `application.log` в
`%AppData%\FirebirdTraceAnalyzer\logs` (Windows),
`~/Library/Application Support/FirebirdTraceAnalyzer/logs` (macOS) или
`~/.config/FirebirdTraceAnalyzer/logs` (Linux). Успешная загрузка оставляет
`Loaded sorts/filters from plugin: {Name} (v{Version})` и `Total custom … registered: N`.

### Плагин не появляется (приложение работает)

| Симптом (в логе) | Причина | Как исправить |
| ---------------- | ------- | ------------- |
| `Plugin '{Name}' … failed in GetSorts()/GetFilters() — skipped` | `GetSorts()`/`GetFilters()` бросил исключение. Вызов обёрнут по-плагинно, поэтому он пропускается. | Держите эти методы чистыми — только `yield return` дескрипторов. Тяжёлую логику выносите в компаратор/предикат. |
| Ошибка загрузки сборки для DLL | Нет публичного конструктора без параметров (или он бросает), поэтому `Activator.CreateInstance` падает и вся DLL пропускается. | Сделайте конструктор `public` и без параметров; не делайте в нём тяжёлой/бросающей работы. |
| `ReflectionTypeLoadException` / нет зависимости | Рядом с DLL нет зависимости или рядом положены SDK-сборки. | Положите свои сторонние зависимости в подпапку; **не** поставляйте `FirebirdTraceParser.dll` / `FirebirdTraceAnalyzer.dll`. |
| В логе вообще нет строки про ваш плагин | DLL лежит в корне `Plugins/`, а не в подпапке — сканируются только подпапки. | Переместите в `Plugins/<name>/YourPlugin.dll`. |
| Ни строки в логе, ни ошибки | Класс `abstract`/интерфейс или не реализует `ISortPlugin`/`IFilterPlugin`. | Сделайте конкретный `public`-класс, реализующий интерфейс. |
| `… with Id '{Id}' overwrites existing one …`; пунктов меньше ожидаемого | Совпадающие id дескрипторов перезаписывают друг друга. | Дайте каждому дескриптору уникальный id с пространством имён. |
| Изменения не подхватились после замены DLL | Приложение не перезапущено или рядом осталась старая DLL с теми же id. | Замените DLL, удалите старую и перезапустите. |

### Ошибки при сортировке или фильтрации (пункт уже в UI)

| Симптом | Причина | Как исправить |
| ------- | ------- | ------------- |
| Список не сортируется/не фильтруется; в строке статуса ошибка фильтрации; список может опустеть | Компаратор/предикат бросил исключение в рантайме — обычно null-ссылка на чужом типе события. Перехвачено, поэтому приложение не падает, но результат не строится. | Всегда сопоставляйте подтип через `is` перед чтением полей; защищайтесь от null; возвращайте нейтральное значение (`false`/`0`) для других событий. |

## Чек-лист

- Класс `public`, не `abstract`, с конструктором без параметров.
- Реализует `ISortPlugin` и/или `IFilterPlugin`.
- Каждый id плагина и дескриптора уникален и с пространством имён.
- Компаратор учитывает флаг `descending`; предикат возвращает `true`, чтобы оставить событие.
- Компаратор/предикат сопоставляет подтип события перед чтением полей.
- В подпапке только ваша DLL (плюс ваши сторонние зависимости) — без SDK-сборок.
- Приложение перезапущено после установки.
