**Плагин** — это обычная .NET-сборка (`*.dll`), которая добавляет в список событий новые
**сортировки** и/или **фильтры**, не изменяя — и не пересобирая — само приложение. При старте
приложение сканирует папку плагинов, загружает каждую сборку в изолированный контекст и регистрирует
то, что она предоставляет. После этого ваши сортировки и фильтры появляются в UI (панели сортировки
и фильтров, а также в конструкторе отчётов) наравне со встроенными.

Плагины нужны, чтобы добавить специфичную для вашей задачи аналитику — «медленные стейтменты»,
сортировку по своей метрике, фильтр по конкретной базе или пользователю — и делиться ею одним файлом
`.dll`.

## Две точки расширения

| Интерфейс       | Метод                                     | Что добавляет     |
| --------------- | ----------------------------------------- | ----------------- |
| `ISortPlugin`   | `GetSorts()` → `IEnumerable<SortDescriptor>`   | варианты сортировки |
| `IFilterPlugin` | `GetFilters()` → `IEnumerable<FilterDescriptor>` | фильтры    |

Оба наследуют общий базовый интерфейс `IAnalyzerPlugin` с метаданными плагина:

```csharp
public interface IAnalyzerPlugin
{
    string Id { get; }       // globally unique plugin identifier
    string Name { get; }     // human-readable name
    string Author { get; }   // author
    string Version { get; }  // version, free-form (e.g. SemVer)
}
```

Одна DLL может содержать **любое количество** классов-плагинов, и каждый класс может реализовать
**один или оба** интерфейса. Загрузчик создаёт экземпляр каждого класса-плагина и собирает все его
дескрипторы.

<Aside type="danger" title="Плагины исполняются с полными правами">
Плагин исполняется с **полными правами приложения** — песочницы нет. Установка плагина равнозначна
запуску любой другой программы на вашей машине. **Собирайте и ставьте плагины только из исходников,
которым доверяете.**
</Aside>

## Что нужно

<Steps>

1. **.NET 10 SDK** — тот же таргет-фреймворк, на котором собрано приложение (`net10.0`).

2. **IDE или редактор** — JetBrains Rider, Visual Studio 2022+ или VS Code с C# Dev Kit. Подойдёт
   любой; плагин — это обычная библиотека классов.

3. **Две SDK-сборки для ссылки** — `FirebirdTraceAnalyzer` (интерфейсы и дескрипторы) и
   `FirebirdTraceParser` (модель событий). Шаблон уже ссылается на обе.

</Steps>

## Быстрый старт

<Steps>

1. **Скопируйте шаблон.** Клонируйте репозиторий и продублируйте проект `TemplatePlugin` или создайте
   новую библиотеку `net10.0` со ссылками на `FirebirdTraceAnalyzer` и `FirebirdTraceParser`
   (точный `.csproj` — в разделе [Сборка и загрузка](./building-and-loading.mdx)).

2. **Напишите плагин.** Добавьте `public`-класс с конструктором без параметров, реализующий
   `ISortPlugin` и/или `IFilterPlugin`, заполните метаданные (`Id`, `Name`, `Author`, `Version`) и
   верните дескрипторы из `GetSorts()` / `GetFilters()`.

3. **Соберите DLL.**

   ```bash
   dotnet build TemplatePlugin
   ```

4. **Установите.** Скопируйте **только DLL вашего плагина** в отдельную подпапку каталога плагинов
   приложения (или воспользуйтесь кнопкой **Установить** на экране плагинов). SDK-сборки копировать
   не нужно — их предоставляет приложение.

5. **Перезапустите приложение.** Плагины обнаруживаются и регистрируются при старте; горячей
   перезагрузки нет. Ваши сортировки и фильтры появятся в UI.

</Steps>
