# Parsing/PostProcessing — пост-проход по списку событий

`DurationPostProcessor` — статический хелпер, который работает **после** разбора: берёт общий
список событий (все загруженные файлы вместе) и вычисляет производные длительности в
`EventBase.Duration`:

- **`TraceFinishEvent`** — время жизни серверного процесса: `fini − init` одной пары
  `(TraceId, HexTraceId)` + совпадающий `SessionId`. Классический нюанс: у Classic все процессы
  пишут в одну `SESSION_N`, поэтому пара ищется по процессу. Длительность ставится, только если
  между init и fini был виден ATTACH этого процесса — иначе процесс жил до начала лога и
  `fini − init` занизил бы время жизни.
- **`DetachDatabaseEvent`** — время жизни подключения: `detach − attach` по ключу
  `(DatabasePath, AttachmentId)` (в одном трейсе бывает несколько баз со своими счётчиками ATT),
  в том числе когда пара лежит в разных файлах.

## API

- `Compute(IReadOnlyList<EventBase>)` — вычисляет и **возвращает** `IReadOnlyList<DurationResult>`,
  события не трогает (безопасно звать в фоне на снимке списка).
- `Assign(IReadOnlyList<DurationResult>)` — записывает `Duration` в события (включая сброс в null
  для событий, чья пара не найдена: повторный расчёт стирает устаревшие значения).

События обходятся по времени через стабильную сортировку (уже упорядоченный список не
пересортировывается); завершённая пара сразу удаляется из рабочего состояния.
