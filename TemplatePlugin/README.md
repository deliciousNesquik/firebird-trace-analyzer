# TemplatePlugin — образец плагина для Firebird Trace Analyzer

Готовый шаблон для написания собственных **плагинов** к `Firebird Trace Analyzer`. Показывает обе
точки расширения — пользовательскую **сортировку** и пользовательский **фильтр** событий
трассировки. Скопируйте этот проект, замените логику на свою — и приложение подхватит расширение
без пересборки самого приложения.

Код примера — в [`Template.cs`](./Template.cs). Этот README объясняет, **что это, как работает,
зачем и куда класть**.

---

## Что такое плагин

Плагин — это обычная .NET-сборка (`*.dll`), которая добавляет в приложение новые **сортировки**
и/или **фильтры** списка событий, не требуя изменений в самом приложении. Приложение при старте
находит плагины на диске, загружает их в изолированный контекст и регистрирует то, что они
предоставляют. После этого ваши сортировки/фильтры появляются в UI (панель сортировки и фильтров,
а также в конструкторе отчётов) наравне со встроенными.

**Зачем:** добавлять специфичную для вашей задачи аналитику (например, «медленные стейтменты»,
сортировка по своей метрике) без форка и пересборки приложения; делиться такими расширениями одним
файлом `.dll`.

---

## Две точки расширения

| Интерфейс        | Метод                          | Что добавляет            |
|------------------|--------------------------------|--------------------------|
| `ISortPlugin`    | `GetSorts()` → `SortDescriptor[]`   | варианты сортировки |
| `IFilterPlugin`  | `GetFilters()` → `FilterDescriptor[]` | фильтры           |

Оба наследуют базовый **`IAnalyzerPlugin`** с метаданными плагина:

```csharp
public interface IAnalyzerPlugin
{
    string Id { get; }       // глобально уникальный идентификатор плагина
    string Name { get; }     // человекочитаемое имя
    string Author { get; }   // автор
    string Version { get; }  // версия (свободный формат, напр. SemVer)
}
```

Классов в одной DLL может быть **сколько угодно**, и каждый класс может реализовать **один или
оба** интерфейса (`ISortPlugin` + `IFilterPlugin` — оба наследуют `IAnalyzerPlugin`). Загрузчик
создаёт экземпляр **каждого** класса-плагина и собирает **все** его дескрипторы. Поэтому к примеру 10
классов (или один класс, возвращающий 10 дескрипторов через несколько `yield return`) дадут 10
сортировок/фильтров.

> **Уникальность `Id`.** Дескрипторы хранятся в словаре по `Id`, поэтому у каждой сортировки и
> каждого фильтра `Id` должен быть **уникальным** — совпадающие `Id` перезапишут друг друга, и
> часть расширений просто не появится.

## Как это работает внутри приложения

1. **Поиск.** `PluginManagerService` при старте сканирует каталог плагинов и **все его подпапки**,
   берёт каждый `*.dll`.
2. **Изоляция.** Каждая сборка грузится в отдельный `AssemblyLoadContext` (`PluginLoadContext`) —
   чтобы возможный конфликт версий зависимостей плагина не ломал приложение.
3. **Инстанцирование.** В сборке находятся все не-абстрактные классы, реализующие `IAnalyzerPlugin`,
   и создаётся по одному экземпляру через `Activator.CreateInstance()`.
   → **У класса плагина обязан быть публичный конструктор без параметров.**
4. **Пропуск SDK.** Сборка `FirebirdTraceParser.dll` намеренно пропускается загрузчиком — **не
   кладите её в папку плагина** (иначе типы SDK продублируются и приведение типов сломается).
5. **Регистрация.** На старте приложение регистрирует найденное: сортировки → в сервис сортировки,
   фильтры → в сервис фильтрации. Дальше они видны в UI и в конструкторе отчётов.

## Версии и обновление плагина

**Загрузчик не смотрит на `Version`.** Поля `Version` и `Author` — чисто информационные: в UI
сортировок/фильтров они **не** отображаются (там только `DisplayName` и `Category`) и попадают
только в лог приложения (`Loaded sorts from plugin: {Name} (v{Version})`). Нет сравнения версий,
нет миграции, нет механизма «обновить плагин». Регистрация ключуется исключительно по **`Id`
дескриптора**.

Что произойдёт, когда автор поднял версию `1.0.0` → `1.1.0`:

| Ситуация | Что в UI / как реагирует загрузчик |
|----------|-------------------------------------|
| Заменили старый DLL новым (та же подпапка, **те же `Id`** дескрипторов) | Чистое обновление: при следующем запуске регистрируется новая логика/имена, пункт в UI тот же. В логе — `(v1.1.0)`. |
| Оставили **обе** версии рядом, **одинаковые `Id`** | Коллизия: грузятся оба класса, но словарь по `Id` перезапишет — победит один (порядок загрузки недетерминирован), второй молча исчезнет. Старый DLL нужно удалить. |
| Обе версии рядом, **разные `Id`** | В UI появятся **оба** пункта как независимые (дубли). |

> Изменения применяются **только при перезапуске** приложения — горячей перезагрузки плагинов нет.
> Правильный сценарий обновления: **заменить** файл DLL на новый (сохранив `Id` дескрипторов) и
> перезапустить приложение.

## Где брать типы

Проект плагина ссылается на две сборки SDK (см. [`TemplatePlugin.csproj`](./TemplatePlugin.csproj)):
`FirebirdTraceAnalyzer` и `FirebirdTraceParser`. Этого достаточно для доступа ко всем нужным типам.

| Namespace                                   | Что там                                                     |
|---------------------------------------------|-------------------------------------------------------------|
| `FirebirdTraceAnalyzer.Interfaces.Plugins`  | `IAnalyzerPlugin`, `ISortPlugin`, `IFilterPlugin`           |
| `FirebirdTraceAnalyzer.Services.Sorting`    | `SortDescriptor`                                            |
| `FirebirdTraceAnalyzer.Services.Filtering`  | `FilterDescriptor`                                          |
| `FirebirdTraceParser.Models.Events`         | `EventBase` и подтипы событий                               |
| `FirebirdTraceParser.Models.ValueObjects`   | `PerformanceInfo`, `AttachmentInfo`, `TransactionInfo`, ... |
| `FirebirdTraceParser.Enums`                 | `FilterType`, `EventType`, `IsolationLevel`, ...            |

## Модель событий

В `comparer`/`predicate` приходит `EventBase` — базовый тип для всех событий (общие поля:
`Timestamp`, `TraceId`). 

**Конкретика — в подтипах:**

- `TraceInitEvent`, `TraceFinishEvent`
- `AttachDatabaseEvent`, `DetachDatabaseEvent`
- `StatementStartEvent`, `StatementRestartEvent`, `StatementFinishEvent`, `FailedStatementFinishEvent`
- `ProcedureStartEvent`, `ProcedureFinishEvent`, `FailedProcedureFinishEvent`
- `TriggerStartEvent`, `TriggerFinishEvent`, `FailedTriggerFinishEvent`
- `ErrorEvent`

Доступ к специфичным полям — через сопоставление с образцом; так вы работаете только с теми
событиями, у которых нужное поле есть, и не падаете на «чужих» типах:

```csharp
if (e is StatementFinishEvent s)
{
    int ms   = s.Performance.ExecuteMs; // время исполнения
    string q = s.Sql;                   // текст запроса
}
```

## Сортировка: `SortDescriptor`

```csharp
new SortDescriptor(
    id:          "my_sort",              // уникальный идентификатор сортировки
    displayName: "My sort",              // имя в UI
    comparer:    Compare,                // функция сравнения (см. ниже)
    isDefault:   false,                  // выбирать ли по умолчанию
    category:    "Analytics",            // группа в списке
    priority:    2);                     // порядок (меньше = выше)
```

**Контракт компаратора** `Func<EventBase, EventBase, bool, int>` — `(a, b, descending)`:

- вернуть `< 0`, если `a` должно идти **раньше** `b`; `0` — если равны; `> 0` — если **позже**;
- флаг `descending` передаёт приложение (текущее направление), и компаратор **обязан его учесть** —
  обычно инвертированием знака результата: `return descending ? -result : result;`

```csharp
private static int CompareByExecuteTime(EventBase a, EventBase b, bool descending)
{
    static int ExecuteMs(EventBase e) => e is StatementFinishEvent s ? s.Performance.ExecuteMs : -1;
    var result = ExecuteMs(a).CompareTo(ExecuteMs(b));
    return descending ? -result : result;
}
```

## Фильтр: `FilterDescriptor`

```csharp
new FilterDescriptor(
    id:            "my_filter",           // уникальный идентификатор фильтра
    displayName:   "My filter",           // имя в UI
    filterType:    FilterType.Boolean,    // тип редактора в UI (см. ниже)
    propertyPath:  "Performance.ExecuteMs", // путь к свойству события (для подписи/подбора значений)
    filterPredicate: KeepEvent,           // функция «оставлять ли событие» (см. ниже)
    category:      "Analytics",
    priority:      2);
```

**Значения `FilterType`** (какой редактор покажет UI):

| Значение             | Редактор                                                                       |
|----------------------|--------------------------------------------------------------------------------|
| `Auto`               | автоопределение по типу свойства, <br/>**(Лучше использовать конкретный тип)** |
| `Boolean`            | простой переключатель вкл/выкл                                                 |
| `EnumMultiSelect`    | список значений enum с чекбоксами                                              |
| `StringMultiSelect`  | список строк + поиск                                                           |
| `NumericRange`       | числовой диапазон (int/long/decimal)                                           |
| `DateTimeRange`      | диапазон дат                                                                   |
| `TextSearch`         | полнотекстовый поиск (SQL, длинные тексты)                                     |

**Контракт предиката** `Func<EventBase, bool>`: вернуть `true`, если событие **должно остаться**
(когда фильтр активен), и `false`, если его надо скрыть. Предикат вызывается для каждого события —
сначала сопоставляйте тип:

```csharp
private static bool IsSlowStatement(EventBase e)
    => e is StatementFinishEvent s && s.Performance.ExecuteMs >= 1000;
```

## Сборка и установка плагина

1. Соберите проект:

   ```bash
   dotnet build TemplatePlugin
   ```

2. Скопируйте **только DLL плагина** (`TemplatePlugin.dll`) в **отдельную подпапку** каталога
   плагинов приложения (DLL должна лежать в подпапке, не в корне `Plugins`):

   | ОС      | Путь                                                                            |
   |---------|---------------------------------------------------------------------------------|
   | Windows | `%AppData%\FirebirdTraceAnalyzer\Plugins\<имя>\TemplatePlugin.dll`               |
   | macOS   | `~/Library/Application Support/FirebirdTraceAnalyzer/Plugins/<имя>/TemplatePlugin.dll` |
   | Linux   | `~/.config/FirebirdTraceAnalyzer/Plugins/<имя>/TemplatePlugin.dll`               |

   `FirebirdTraceParser.dll` и `FirebirdTraceAnalyzer.dll` класть **не нужно** — их предоставляет
   приложение. Если у вашего плагина есть **свои** сторонние зависимости — положите их рядом с DLL
   плагина в ту же подпапку.

3. Перезапустите приложение — плагин подхватится при старте (сортировки/фильтры появятся в UI).

## Как написать свой плагин (по шагам)

1. Скопируйте этот проект (или создайте `net10.0`-библиотеку с ссылками на `FirebirdTraceAnalyzer`
   и `FirebirdTraceParser`).
2. Создайте `public`-класс с конструктором без параметров, реализующий `ISortPlugin` и/или
   `IFilterPlugin`, и заполните метаданные (`Id`, `Name`, `Author`, `Version`).
3. В `GetSorts()`/`GetFilters()` верните нужные дескрипторы; реализуйте свой компаратор/предикат.
4. Соберите и установите DLL (см. выше), перезапустите приложение.

## Возможные ошибки и как их исправить

Ошибки делятся на два класса по последствиям:

- **Загрузка** (поиск/инстанцирование DLL) обёрнута в `try/catch` пофайлово — сбойный плагин
  **молча пропускается**, в лог пишется предупреждение, приложение работает. Плагина просто нет в UI.
- **Регистрация** (`GetSorts()`/`GetFilters()`) вызывается в конструкторе главного окна **без**
  `try/catch` — исключение отсюда **уронит запуск приложения**.

> **Где смотреть логи:** `application.log` в папке
> `%AppData%\FirebirdTraceAnalyzer\logs` (Windows) ·
> `~/Library/Application Support/FirebirdTraceAnalyzer/logs` (macOS) ·
> `~/.config/FirebirdTraceAnalyzer/logs` (Linux). Успешная загрузка оставляет строку
> `Loaded sorts/filters from plugin: {Name} (v{Version})` и `Total custom … registered: N`.

### 🟥 Критично: приложение не запускается

| Симптом | Причина | Как исправить |
|---------|---------|---------------|
| Приложение падает/не открывается сразу при старте; в логе стектрейс из `RegisterCustomSorts`/`RegisterCustomFilters` | **`GetSorts()`/`GetFilters()` бросает исключение** (NRE, обращение к внешнему ресурсу, деление и т.п.). Регистрация идёт в конструкторе без перехвата. | Держите эти методы простыми и «чистыми»: только `yield return new …Descriptor(...)`. Не обращайтесь к файлам/сети/состоянию, не бросайте исключения. Тяжёлую логику выносите в сам предикат/компаратор. |

### 🟨 Плагин не появился в UI (приложение работает)

| Симптом (в логе) | Причина | Как исправить |
|------------------|---------|---------------|
| `Ошибка при обработке файла {dll}` | У класса плагина **нет публичного конструктора без параметров** (или конструктор бросает) — `Activator.CreateInstance` падает, и **вся DLL пропускается**. | Сделайте конструктор `public` без параметров; не делайте в нём тяжёлую/бросающую работу. |
| `Не удалось загрузить типы из сборки {dll}` (ReflectionTypeLoadException) | **Не хватает зависимости** плагина рядом с DLL, **или** рядом положены SDK-сборки. | Положите **свои** сторонние зависимости в ту же подпапку. **Не** кладите `FirebirdTraceParser.dll`/`FirebirdTraceAnalyzer.dll`. |
| В логе нет ни строки про ваш плагин | **DLL лежит в корне `Plugins/`, а не в подпапке** — сканируются только подпапки. | Положите DLL в подпапку: `Plugins/<имя>/YourPlugin.dll`. |
| В логе нет вашего плагина, ошибок тоже нет | Класс **`abstract`/`interface`** или **не реализует** `ISortPlugin`/`IFilterPlugin` — такие типы отсеиваются. | Сделайте конкретный `public`-класс, реализующий нужный интерфейс. |
| Плагин загрузился (есть в логе), но `Total … registered` **меньше**, чем ожидалось; часть пунктов отсутствует | **Дублирующиеся `Id` дескрипторов** — словарь перезаписывает совпадающие. | Дайте каждому `SortDescriptor`/`FilterDescriptor` **уникальный `Id`**. |
| Приложение не подхватило изменения после обновления DLL | Приложение **не перезапущено** (горячей перезагрузки нет), либо рядом остался старый DLL с теми же `Id`. | Замените DLL и **перезапустите** приложение; уберите старую версию (см. «Версии и обновление плагина»). |

### 🟧 Ошибка при работе (сортировка/фильтрация уже в UI)

| Симптом | Причина | Как исправить |
|---------|---------|---------------|
| Список событий не сортируется/не фильтруется, в статус-баре `Filtering error: …`, список может стать пустым | **Компаратор/предикат бросает исключение** во время работы (обычно NRE на «чужом» типе события). Это перехватывается — приложение не падает, но результат не строится. | Всегда сопоставляйте тип через `is` перед доступом к полям; защищайтесь от `null`; не бросайте исключения. Для «чужих» событий возвращайте нейтральное значение (`false`/`0`). |

## Чек-лист и типичные ошибки

- ☐ Класс `public`, не `abstract`, с конструктором без параметров.
- ☐ Реализует `ISortPlugin` и/или `IFilterPlugin`.
- ☐ **Уникальные `Id`** у плагина и у каждого дескриптора — иначе перекроют друг друга или встроенные.
- ☐ Компаратор учитывает флаг `descending`; предикат возвращает `true` = «оставить событие».
- ☐ В компараторе/предикате — сопоставление с образцом по нужному подтипу события.
- ☐ В подпапку плагина попал только его DLL (+ свои сторонние зависимости), **без** SDK-сборок.
- ☐ После установки приложение перезапущено.
